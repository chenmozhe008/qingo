# 小清垃圾清理机制审计

2026-11-22，本机 macOS 27。对照小清 1.20.2、待验收的 1.22.0、macOS 存储管理、Mole、腾讯柠檬清理和 CleanMyMac。以下数据通过只读扫描取得，未执行同类工具的清理操作。

## 为什么会出现「小清 5 MB，别的工具 10 GB」

| 产生差异的位置 | 本机证据与含义 |
| --- | --- |
| 清理口径 | 小清把文件移动到废纸篓。第二款工具若永久移除同一批文件或清空已有废纸篓，才可能出现一次明显的可用空间变化。两款工具依次执行时，第二款的结果还可能包含第一款已移走的文件。当前终端无法读取本机废纸篓，未把它按 0 B 计算，也不能据此解释某次具体差值。 |
| 应用重建缓存 | 最近五次小清记录共移动 102 项，记录中的失败数均为 0。回查原路径，89 项已出现新对象，创建时间都晚于相应清理时间。清理记录里的字节数只表示移走过的内容，不能当作永久释放量。 |
| 小型缓存门槛 | 上一份保存的快速扫描有 177 项低于 1 MB，旧版全部排除，文件大小合计约 35 MB。新版把小项合计，达到 1 MB 则纳入清理，并可展开查看。 |
| 扫描范围及活跃数据 | Chrome、Edge 可明确归类的网页和代码缓存共约 1.04 GB，旧版已通过整个缓存父目录覆盖其中部分。另有 Codex 运行环境约 1.75 GB、会话约 10.83 GB、Playwright 浏览器约 1.11 GB、npx 临时安装约 0.45 GB。它们占空间，也可能是活跃环境、按版本安装的工具或个人记录。 |
| 空间算法 | 旧结果通常累加逻辑文件长度。新版同时记录文件分配块，稀疏文件按实际分配量估算，有其他硬链接的文件保守记 0。APFS 克隆、快照和系统可清除空间仍会影响最终可用容量。 |

## 同机只读对照

基线使用仓库中的 1.20.2 源码，在临时目录构建，再与 1.22.0 对同一台 Mac 做快速扫描。两次扫描间浏览器保持运行。均未执行清理，这些数字表示候选范围与统计口径。

| 指标 | 1.20.2 | 1.22.0 |
| --- | --- | --- |
| 快速扫描耗时 | 31.19 秒 | 22.86 秒 |
| 供一键清理的数字 | 3.73 GB，旧版按文件逻辑长度，包含 Codex 运行环境等旧规则 | 0.57 GB，按已分配块估算 |
| 需要退出浏览器 | 没有单列，浏览器相关父目录进入一键结果 | 1.06 GB，按已分配块估算 |
| 曾因单项不足 1 MB 被隐藏的内容 | 180 项，逻辑大小约 35 MB | 小项合并，超过总门槛后显示 |

快速扫描对明确的缓存或共享存储目录直接做一次大小遍历，避免对每个内部对象反复判断属于哪款工具。扫描器仍检查卷边界，跳过链接目标，并拒绝把遍历不完整的缓存根标记为可批量处理。

## 同类工具的做法

| 工具 | 已核对的规则 | 小清采用的做法 |
| --- | --- | --- |
| macOS / Finder | 废纸篓项目在清空前仍在磁盘上。存储管理的可用空间包含系统可按需清除的空间。系统数据包含多种由 macOS 管理的资源。 | 清理结果写明已移到废纸篓的项数与估算占用，显示成功、重建和跳过原因。磁盘可用空间继续读系统值。 |
| CleanMyMac | 按系统垃圾、废纸篓、AI 数据等类别分开处理。默认选择和排除按规则维护，清理后可查看日志。 | 保留默认安全选择，单列需要在原工具中管理的存储。最近的清理可从「扫描」菜单打开。 |
| Mole | 按程序和目录设白名单，有预演、运行进程保护、路径与身份复核；CLI 缓存操作通常直接删除。其审计记录了模型和活跃 SQLite 缓存被扫中的具体风险。 | 浏览器缓存按具体目录选择，运行时明确跳过；移动前复核路径、身份及受保护子项。Codex 运行环境和模型目录归原工具管理。 |
| 腾讯柠檬清理 | 公开规则把 Chrome、Edge 的具体网页缓存从通用规则排除，再按应用独立处理。还单列 Mail、Safari 等较敏感项目。 | Chrome 系列、Edge、Brave、Chromium、Firefox 采用专门目录规则。Safari 和邮件继续由原应用处理。 |

## 1.22.0 的清理边界

- **可批量移到废纸篓**：已识别应用缓存与开发构建缓存、符合条件的旧版本副本、浏览器网页及渲染缓存、Codex 界面缓存、30 天前的用户诊断报告。浏览器需要退出；诊断报告按单文件处理。旧版浏览器签名副本仍采用保守估算。
- **明确确认后处理**：大文件、安装包、可识别的 iPhone/iPad 本机备份、重复文件。iCloud 下载项和本地快照使用区别于废纸篓的系统接口，单独提示后确认。
- **在原工具中管理**：uv 包存储、pnpm 共享存储、npx 临时安装、Codex 运行环境。微信/飞书文件、达芬奇渲染缓存和 Final Cut 资源库仍保留应用内入口或处理说明。
- **保护**：会话和凭据、浏览器 Cookie 与离线网站数据、云盘文件、模型、Playwright 安装、项目源文件、系统组件。废纸篓的永久清空由用户在 Finder 完成。

## 仍需实测的范围

- 在同一个隔离样本或同一快照还原后的两个副本上比较两款产品，逐项记录扫描候选、被处理的原路径、废纸篓变化和 macOS 可用空间。按项目选项明确是否计入快照、下载文件、容器、设备备份及废纸篓。
- 本机读取浏览器的部分应用数据目录、废纸篓和设备备份受到权限限制，这些目录的实际占用未计入本次只读盘点。已安装的日常版本没有被替换。
- 继续评估 Adobe 媒体缓存等长时间写入的 SQLite 工作区。Adobe 建议先关闭项目再从应用内清理全部媒体缓存。本机这些目录几乎没有可用样本，当前没有把它们当作新增空间收益。
- 第三方工具的 10 GB 缺少对应的工具名、项目清单及前后容量读数。现有证据能解释差异的机制，不能还原那次操作的组成。

### 实现优先级与验收条件

1. **先修两类会误算空间的数字。** 在总览和清理记录中清楚显示废纸篓占用、测量时间、权限不足和仍待释放的状态。对已验证共享的数据给单独说明。记录三个时点的磁盘容量：操作前、移动到废纸篓后、用户主动处理废纸篓之后。禁止以不同磁盘的容量作差。
2. **建立 Chromium 旧副本和更新暂存的窄规则。** Chromium 正在使用的副本以及版本未知的副本保持保护。更新场景覆盖旧安装包、当前待更新、不同渠道、安装器运行中、归属未知五类。只有版本过期且可独立验证的项目进入确认列表。
3. **把 Playwright 和 npx 做成开发缓存的逐项管理。** 先交付只读预演，对已登记、登记缺失、安装中、自定义缓存位置分开显示。操作前回读登记和进程，并保持撤销可用。验收用两套真实浏览器版本和至少一项跨项目依赖，验证保留版本能启动、候选可重新下载、撤销能复原。未实测前将本机 **557 MB** 记为发现的候选占用，实际释放量留空。
4. **用同基线样本验收第三方清理。** 两套独立测试环境使用同一份样本。项目包含大废纸篓、克隆副本、活跃缓存、旧安装包和共享开发环境。记录候选目录、实际被移动或删除的内容、误选项及前后可用空间。后续取得另一工具的清单时用同一口径比对。

本轮完成只读盘点、共享数据抽样和规则审阅。未执行垃圾清理或修改小清代码。

## 1.23.0 实施与扫描卡顿排查

- 在已安装的 1.22.0 上重跑快速扫描并读取进程采样。界面主线程多次停在 `MainView.volumeCapacity` 对 macOS CacheDelete 服务的同步查询中，后台扫描仍在遍历缓存。1.23.0 把 Finder 口径的容量查询移出界面线程，合并高频扫描事件，并让垃圾扫描先交付结果，聊天占用随后在后台更新。
- 清理记录保存本次涉及的同卷容量读数，提供移动前、移动后和手动复测三个时点。差值按文件系统可用块计算，也包含这段时间内其他应用产生的磁盘变化。空间分布把废纸篓和同版本签名副本单独展示。0 B 和读取失败分别呈现。
- Playwright 默认目录可以按版本预览。只读匹配客户端登记，已登记、未发现引用、登记不完整和缺失安装标记分开显示。检查安装锁，遇到自定义目录时提示扫描范围。
- Sparkle、Electron Updater 和 ShipIt 的更新暂存从通用规则分离。普通缓存父目录含更新暂存时，不会整目录移动，仍可单独识别常见网页缓存。浏览器签名副本只能在浏览器退出后、确认低于当前安装版本时进入清理。

已在本机签名安装 1.23.0 开发版，并实际跑完快速扫描和完整扫描。结果分别记录 178,886 和 794,441 项。新版的两次扫描采样均未在主线程看到原来的同步 CacheDelete 查询。另用临时文件验证了移动前后记录来自同一磁盘以及撤销流程。
