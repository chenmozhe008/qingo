# 小清清理能力改进方案（2026-11-06 调研稿，待用户拍板）

## 结论

小清清得少，原因有三个，加缓存规则只能解决其中一个：

1. **看的范围太窄**：完整扫描只量个人文件夹（253 GB），整盘已用约 460 GB，系统临时目录、应用程序、/Library 共 200 多 GB 没看。本机最大的一块「白捡」空间（Chrome 签名副本）就在没看的地方。
2. **能一键清的只有「缓存」**：这台 Mac 的常规缓存已经清过一轮（Adobe、达芬奇、剪映缓存都接近 0），所以快速扫描只剩 1.1 MB。真正占地方的是旧版本残留、聊天记录、AI 会话、资料、录音、不用的 App，这些都不是缓存。
3. **数字没算对 APFS**：同一份数据被克隆多份时，按文件大小加总会虚报（Chrome 副本量出 12.8 GB，实际约 2–3 GB）。改进后显示的必须是删掉后真正腾出的空间。

按最高原则（只列能放心删的）扩大一键清理，本机预计能多清 **6–9 GB**；再加上「一步确认」的大项，可处理空间在 **50 GB 以上**。

## 本机实测（2026-11-06，可用 31.8 GB / 共 494 GB）

| 位置 | 大小 | 小清现在 | 能不能清 |
|---|---|---|---|
| 系统临时目录：Chrome/Edge 旧版签名副本 | 量出 13.9 GB，实际约 2–3 GB | 没扫到 | 浏览器没在运行时可放心删（Chromium 自己的临时副本） |
| 系统临时目录：clang 模块缓存、过期临时文件 | 约 3 GB | 没扫到 | 可重建 |
| Codex 运行环境、Claude Code 旧版本 | 约 2 GB | 没扫到 | 只删旧版本，保留当前版本 |
| `.codex` 会话 9.7 GB + 历史库 3.8 GB + 生成图 2.7 GB | 16 GB | 已定不显示 | 对话记录，需用户决定 |
| 微信 / 企业微信 / 飞书 | 38.9 GB | 只给应用内清理步骤 | 聊天文件，只能在应用里删 |
| 同步空间（资料文档） | 34.9 GB | 列为大文件 | 用户资料 |
| 应用程序 | 53.5 GB | 卸载页列出 2 个长期未用 | 需用户决定 |
| 录音工作台 + 闪电说 | 15.7 GB | 闪电说只列 15 天前录音 | 用户数据 |
| 飞书 `aha` 目录 | 5.9 GB | 只读 | 用途待查 |
| 通用二进制里的 Intel 代码 | 6.9 GB | 无 | **不建议**：要改动 App 本身，会破坏签名、影响更新 |
| 沙盒容器（Containers / Group Containers） | 约 60 GB 未摸清 | 部分 | 需小清用完全磁盘访问量（终端读会弹授权框） |

## 同类工具怎么做（看源码或官方说明）

- **Mole（tw93，开源，2.2 万行清理规则）**：规则最全。值得照抄的：
  - Chromium 系浏览器签名副本：只删「浏览器没在运行 + 版本不是当前版」的，并注明 APFS 共享数据、大小不准；
  - 各类工具的**旧版本**（Claude Code、Codex、Cursor Agent、Autodesk Fusion 一次 60 GB），只留当前版本；
  - 剪映只清 `User Data/Cache` 里生成的中间文件，导出和素材不碰；
  - Adobe Media Cache、Autodesk 缓存：**相关程序开着时跳过**（删正在写的 SQLite 缓存曾把磁盘写满，issue #1390）；
  - Time Machine 本地快照、失败的备份、iOS 固件、模拟器设备、Homebrew 旧版本；
  - `purge`：项目构建产物（node_modules、target 等），按 git 状态保护；
  - `installer`：找安装包（dmg/pkg/zip）；
  - 每一类都有「预演」，先列后删。
- **腾讯柠檬清理（开源）**：规则库是一份 XML，分「系统垃圾 / 应用垃圾 / 开发垃圾」，覆盖系统日志（/private/var/log、诊断报告）、iOS 备份和固件、Xcode 全套、无用语言文件、下载文件夹。语言文件和下载文件夹需人判断，不适合小清的一键原则。
- **CleanMyMac（官方说明）**：系统垃圾（缓存、日志、损坏的偏好设置、Xcode 垃圾、语言文件）默认全选；**未使用的磁盘映像和文稿旧版本不自动选**。另有邮件附件、废纸篓、重复文件、「Space Lens」空间地图、大文件和旧文件。

小清的独特点（AI 工具、创作软件、微信等国内软件）是对的方向，差距主要在：**范围（系统临时目录、旧版本）**、**空间地图**、**真实大小**。

## 改进方案

### 一、一键清理扩到「可放心删」的新三类（预计本机 +6–9 GB）

1. **浏览器旧版签名副本**：Chrome、Edge、Brave、Chromium，判据照 Mole（浏览器未运行、属于当前用户、副本版本 ≠ 已装版本）。
2. **工具旧版本**：Claude Code、Codex 运行环境/暂存、Cursor Agent、Chrome 自动化用的旧浏览器、各 App 更新器留下的旧安装包；永远保留当前版本和上一版。
3. **系统临时目录里的可重建项**：`/var/folders/*/C` 下的 clang 模块缓存等，`T` 下 3 天以上没人用的临时文件（排除正在被打开的）。

仍照「软件开着也照清」。Mole 对 Adobe Media Cache、Autodesk 做了「开着就跳过」，起因是直接删除正在写的缓存把磁盘写满；小清是移到废纸篓（同盘只改路径），不是同一种情况，10-30 也已否过这个提议，不照抄。

### 二、显示的大小改成「实际能腾出的」

- 用 APFS 的已分配块和克隆判断（同一文件系统对象只算一次，与旧版本共享的不算）；拿不准时写「约」并取保守值。
- 清理后用磁盘可用空间的前后差额核对，结果条写实际腾出了多少。

### 三、完整扫描改成「整台 Mac 的空间地图」

- 范围从个人文件夹扩到整盘：应用程序、/Library、系统临时目录、沙盒容器、iCloud 已下载文件，外加系统卷/预启动/虚拟内存的固定部分（标「系统占用，无法清理」）。
- 沙盒容器目前按规则不读（读会弹系统授权框）。要先实测：开着完全磁盘访问时只量大小会不会弹框；会弹就只显示容器合计，不往里钻。
- 总览加一张按占用排序的地图（类似 DaisyDisk / Space Lens），每块写「是什么、能不能清、怎么清」，点进去一层层看。回答「空间去哪了」，即使不能清也说清楚。
- 用户之前否过「目录占用」分类（看不懂、不能操作），所以地图每一块必须落到一个操作或一句明确说明，不出现裸目录名。

### 四、大项做成「一步确认」，不进一键清理

符合「大文件与工程除外」那条例外的思路，单独一个区块，每项一句后果、一个按钮：

| 大项 | 本机规模 | 做法 |
|---|---|---|
| 长期未用的 App | 53.5 GB 中的一部分 | 已有卸载页，总览直接给「N 个 App 超过 90 天没打开，共 X GB」 |
| 微信 / 企业微信聊天文件 | 38.9 GB | 保持应用内清理指引（安全红线不变），总览给数字和入口 |
| AI 会话记录 | 16 GB | 需你决定是否重新开放：之前定过 Codex 对话不显示 |
| 安装包、重复文件、超大旧文件 | 待量 | 新增重复文件查找（只比对 ≥ 50 MB 的文件，按内容哈希） |

## 需要你拍板的三件事

1. **完整扫描改成整盘空间地图**：可以吗？这会推翻 10-21 前「目录占用」被删的做法，但每块都会给操作或说明。
2. **AI 会话记录**：Codex 30 天前的对话要不要作为「一步确认」项出现（目前完全不显示）？
3. **先做哪块**：建议顺序是 一（多清 6–9 GB，最快见效）→ 二（数字可信）→ 三（地图）→ 四。

# 第二轮调研：面向所有用户的「清得多又安全」（2026-11-06 下午）

## 成熟软件的安全逻辑（一手资料）

| 做法 | 来源 | 小清现状 |
|---|---|---|
| **规则库而不是猜**：只删规则库里认得的东西，系统目录整体进忽略名单；默认只动自动生成的数据，不动个人文件 | CleanMyMac「Safety Database」（2008 年起维护，每次扫描都查） | 有（`SafetyPolicy`、`CreativeApps`、`ChatCache`、`Leftovers`），已一致 |
| **用户忽略名单**：用户可以把某项永久排除 | CleanMyMac Ignore list、Mole whitelist | **没有** → 补 |
| **删前在最后一步再判断一次**（扫描完到点清理之间情况可能变了） | Mole `safe_remove` 在最终一步复核 | 有（`TrashService` 复核规则和身份） |
| **路径安全**：拒绝相对路径、`..`、符号链接（包括上级目录是链接）、不属于当前用户的 | Mole `validate_path_for_deletion` | 部分有（遍历跳过链接、`realpath` 规范化）；上级目录是链接的情况待补测试 |
| **进回收站可撤销 + 操作日志** | Mole、CleanMyMac | 有（撤销、`CleanupLog`） |
| **永不碰的类别**：钥匙串、密码、VPN/代理配置（Clash 等）、浏览器历史和 Cookie、`~/Library/LaunchAgents` 里用户自己的自动化、iCloud 云盘、备忘录、信息附件 | Mole 审计文档「Protected Categories」 | 规则只放行缓存，这些本来不会被列出；卸载流程要补一道守卫：卸载 VPN 类 App 时配置默认不勾 |
| **卸载时同厂商兄弟应用保护** | Mole sibling guard | 有（同厂商前缀判断） |
| **有疑问就跳过**：读不到进程表、读不到属主时当作「在用」 | Mole 三态判断 | `Leftovers` 已照做 |

## 普通用户的大头（这台 Mac 上不明显，但别人的电脑上常见）

| 项目 | 常见规模 | 安全做法 |
|---|---|---|
| iPhone / iPad 备份（MobileSync） | 每台设备 10–100 GB | 一步确认：列出设备名、备份日期，只建议删旧设备、旧备份 |
| iOS 固件（.ipsw） | 每个 5–8 GB | 可重新下载，可进一键清理 |
| 下载文件夹里**已安装 App 的安装包**（dmg/pkg/zip） | 几 GB | 比对 /Applications 里同名 App 已装，标「已安装」，一步确认 |
| Time Machine 本地快照 | 几到几十 GB，显示为「系统数据」 | 说明清楚是什么，提供「释放」（系统命令 `tmutil thinlocalsnapshots`），不碰外接备份盘 |
| iCloud 云盘已下载的文件 | 可能很大 | 「移除下载项」只删本机副本、云端保留（系统接口 `evictUbiquitousItem`），一步确认 |
| 重复文件 | 视情况 | 只比 ≥ 50 MB、内容哈希一致的；保留一份，一步确认 |
| 邮件附件下载 | 几百 MB 到几 GB | 可在邮件里重新下载，一步确认 |
| 「系统数据」里 macOS 自动下载的更新包、Apple 智能模型 | 6–20 GB | 小清动不了也不该动；在空间地图里说明是什么、怎么处理（装上更新或关掉自动下载） |

## 不做的（风险大于收益）

- 删 App 里的语言包、Intel 代码：会破坏签名、影响更新（CleanMyMac 也把语言文件放在默认不选）
- 需要管理员密码的系统日志（/private/var/db/diagnostics 等）：系统自己会滚动清理，收益小，要密码会吓到普通用户
- 清空废纸篓：永远由用户自己做

## 修订后的路线

1. ~~第一块：浏览器旧版副本、Clang 编译缓存~~（1.17.0 已完成）
2. **第二块：信任与安全底座**——忽略名单（右键「不再清理此项」）、路径安全补测试、卸载 VPN/代理类 App 时配置默认不勾；结果条写明「清空废纸篓后腾出 X」，下次打开时如果废纸篓已清空，显示实际腾出的空间
3. **第三块：普通用户的大头**——iOS 固件、已安装 App 的安装包、iPhone 备份、Time Machine 本地快照
4. **第四块：整台 Mac 的空间地图**，包括「系统数据」里系统自己下载的东西的说明
5. **第五块**：iCloud 移除下载项、重复文件

- 1.19：iPhone / iPad 系统更新文件（一键）、iPhone 备份（确认后删）、已装 App 的安装包标「已安装」
- 1.20：空间分布页（1.20.2 放大字号、按类别排序、修色块超出）

## 待办（按建议顺序）

1. **重复文件**：只比 ≥ 50 MB、内容哈希一致的文件，保留一份，一步确认；不进一键清理
2. **iCloud 云盘「移除下载项」**：`FileManager.evictUbiquitousItem`，只删本机副本、云端保留，一步确认
3. **AI 工具、命令行工具的旧版本**：Claude Code（`~/.local/share/claude/versions`）、Cursor Agent、Codex 运行环境等，保留当前版和上一版、跳过正在运行的（照 Mole `clean_dev_ai_agents`）；作者本机没有可删的，要用造的假目录测
4. **Time Machine 本地快照**：说明是什么，提供释放（`tmutil thinlocalsnapshots`）；作者本机没有快照，实测要临时建一个（先告诉用户）
5. **空间分布点出「系统更新」**：更新准备文件在管理员才能读的位置量不到大小，先在「其他」块说明里写清并加「前往更新」按钮（打开系统设置的软件更新）

## 不做

- 清空废纸篓后显示实际腾出多少：清空由用户在访达里做，小清不在场，事后差额会混进系统更新等变化，数字不可信
- 删 App 里的语言包、Intel 代码；需要管理员密码的系统日志；自动清空废纸篓


## 2026-11-22 · 1.21.0 开发版

- **重复文件**：从「空间分布」选择文件夹，按文件大小和 SHA-256 分组，逐项确认。清理前重新核对待移除文件和保留副本。排除受保护的应用数据、项目包、硬链接及云端占位文件。
- **iCloud 下载项**：单选已有本机副本且已完成同步的 iCloud 云盘文件，经确认后调用系统接口卸载下载副本。
- **旧版本**：快速和完整扫描识别原生安装的 Claude Code、Cursor Agent。当前版本无法确认时跳过对应工具，移动前重新核对版本和使用状态。
- **本地快照**：从启动盘读取 Time Machine 快照，确认后请求 macOS 尝试释放约 1 GB，再回读快照列表。保留 Time Machine 设置入口。
- **软件更新**：「空间分布」的「其他」补充更新准备文件的说明，提供「前往更新」。

**剩余**：Codex 运行环境和更新暂存需要独立核对安装器规则后再开放。iCloud 的真实移除和 Time Machine 对真实快照的释放仍待验收。
